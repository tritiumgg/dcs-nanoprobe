# Your first campaign

The hello campaign is the smallest program that runs a campaign through the API. It
exists in three languages, and each does the same thing:

| Example | Language | Client code |
|---|---|---|
| [examples/hello-rust](../examples/hello-rust) | Rust | the workspace's `nanoprobe-proto` crate |
| [examples/hello-python](../examples/hello-python) | Python | generated with `grpcio-tools` |
| [examples/hello-kotlin](../examples/hello-kotlin) | Kotlin | generated by the Gradle protobuf plugin |

Each example's README has its build and run commands.
[api-clients.md](api-clients.md) shows how to generate a client for any language from a
release's schema.

## Run it without DCS

The fake sidecar, `nanoprobe-fake-sidecar`, is the real API server over a simulated
DCS. It lets you write and test a controller with no DCS at all. It is in each release
archive; from the unpacked folder, run:

```sh
./nanoprobe-fake-sidecar --listen 127.0.0.1:47311
```

On Windows the program is `nanoprobe-fake-sidecar.exe`. On a Mac, use the macOS
archive, which holds this program alone ([install.md](install.md), "macOS"). In a
checkout, run `mise install`, then
`cargo run -p nanoprobe-fake-sidecar -- --listen 127.0.0.1:47311`.
[controller-guide.md](controller-guide.md), "Test without DCS", has its options and
its limits.

In another terminal:

```sh
cargo run -p nanoprobe-hello --bin hello-campaign -- http://127.0.0.1:47311
```

The hello prints each step and ends with a line such as:

```
hello campaign done: campaign 1763020000000 group 1 revision 9 events 4
```

## Run it on a DCS server

You need:

- the agent installed and the sidecar running ([install.md](install.md)), with
  `nanoprobe doctor` passing;
- a Caucasus template, `Caucasus.miz`, in the sidecar's mission folder
  ([mission-templates.md](mission-templates.md)): the hello's campaign is on Caucasus;
- a server nobody is flying on. Activating a campaign loads the campaign's mission, as a
  mission change does.

Where the hello can reach the API depends on how the sidecar runs:

- **The sidecar runs as a program.** It listens on the machine's loopback. Run the hello
  on that machine, or forward the port from yours, for example with
  `ssh -L 47311:127.0.0.1:47311 <server>`, and run the same command as above.
- **The sidecar runs in a container beside a DCS container.** It listens on the DCS
  container's loopback, which neither the host nor a forwarded port reaches. Give it a
  listener on the container's address, a tokens file and a published port, as
  [deploy/README.md](../deploy/README.md) describes. Then give the hello the published
  address as its argument, as `http://<host>:<port>`, or set `NANOPROBE_ADDR` to it and
  leave the argument out. The argument wins over the variable.

If the sidecar has a tokens file, put a token of the `controller` role in
`NANOPROBE_TOKEN`.

To watch what the hello does from a second terminal, with the same `NANOPROBE_ADDR` and
`NANOPROBE_TOKEN`:

```
nanoprobe watch world
nanoprobe watch events
```

## What the hello does

1. **`Hello`.** It names itself and its schema version, and learns the server's version
   and its own role.
2. **`AcquireLease`.** One controller at a time may change things. The hello takes the
   lease and renews it at a third of its lifetime. Every changing call carries the lease
   and an idempotency key, so a call sent twice is applied once.
3. **`CreateCampaign`** with `activate`. A campaign is one persistent world with its own
   store. Activating it writes its mission from the map's template, loads that mission,
   and suspends the campaign that was active.
4. **`SubscribeEvents`** from sequence 0. Events are numbered, so a client that
   reconnects continues where it stopped.
5. **`PutGroup`.** It describes a ground group, two M-113s, with a route order of one
   kilometer. The call returns when the sidecar has stored the group, not when DCS has
   spawned it. The sidecar then makes DCS match the stored state.
6. **`ListWorld`, then `WatchWorld`** from the listed revision. The hello waits until
   the group's state is `live`, which means DCS holds it, and until the lead's position
   is within 50 m of the route's end.
7. **`ReleaseLease`.**

The campaign stays active when the hello ends, and its group stays in DCS. Each run
creates a new campaign. `SuspendCampaign`, `FinishCampaign` and `DeleteCampaign` end
one; `ListCampaigns` shows them all.

## Where to go next

- **The world model.** [spec/world.md](../spec/world.md) defines entities, their
  lifecycle states, and what the platform manages. Units a player flies and units placed
  in the Mission Editor are observed, not managed.
- **Simulating without DCS.** A group can be `virtual`: the campaign holds it and DCS
  does not. `Materialize` and `Dematerialize` move a group between the two, and only the
  controller decides when.
- **Freshness.** [controller-guide.md](controller-guide.md), "Freshness", says how old
  each value can be. `GetServerStatus`
  reports the period each sampling tier achieved.
- **Restarts.** Stop the sidecar while a convoy drives and start it again: the campaign
  carries on. After a DCS restart the sidecar must be started again too; the groups on
  the map DCS loaded are then spawned from their stored state, and the campaign's next
  `Reload` loads its own mission ([spec/persistence.md](../spec/persistence.md),
  "Restore").
- **Errors.** [spec/errors.md](../spec/errors.md) lists every error a call can return,
  the roles, and the health verdicts.
