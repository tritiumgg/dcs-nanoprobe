## Method

The same as S4 (docs/results/2026-11-11-first-dll-and-spikes.md, "E25"). The agent holds
a non-blocking loopback TCP pair and makes one `send` and one `recv` each frame, 600
frames for each size. `sock_frame` is the code S4 ran.

`e25-sysframe.lua` times, in the hook state for 600 frames, the calls the pump's
system-call frame makes with no sidecar connected (`driver::frame_with`,
`Link::syscall`, spec/transport.md, "Handshake"): an `accept` on a non-blocking loopback
listener with nothing waiting, the check for the kill-switch file, the check for the
shim reload request, and the log flush with one record held and with none. Both files
are absent, as they are on almost every such frame. With a sidecar connected the
frame's socket call is a `recv` that would block, which `e25-socket.lua` measures at
size 0.

S4 ran with the host's default power saving: idle states C1 to C10 and the default
energy preference. Before this run the host was limited to C1 with the `performance`
energy preference, and its kernel was updated. That most of S4's cost came from the
power saving is an inference from this before-and-after on the same host, not a
controlled comparison. It agrees with a measurement made outside this project (PRIOR,
not re-checked here): idle cores in C6 to C10 took 85 to 890 µs to wake and ran at about
1.3 GHz; each Wine socket call makes two round trips to `wineserver`, and each wakes
both processes; limiting idle states to C1 alone gave a 512-byte frame of 156–159 µs at
p50 and 215–216 µs at p99. That measurement was not made inside DCS. C1 alone does not
explain the rest of the difference, down to this run's 105 µs at p50; the energy
preference and the kernel both changed, and neither was measured on its own
(UNVERIFIED).

## E25: socket cost per frame

Microseconds, 600 frames a size:

| Bytes | send p50 | send p99 | recv p50 | recv p99 | frame p50 | frame p99 |
|---|---|---|---|---|---|---|
| 0 (idle: recv would block) | 34.8 | 60.1 | 28.1 | 46.3 | 62.9 | 102.5 |
| 64 | 48.9 | 82.8 | 35.2 | 55.4 | 84.1 | 136.4 |
| 512 | 59.7 | 78.2 | 45.1 | 55.9 | 105.0 | 131.2 |
| 4,096 | 51.8 | 81.3 | 36.5 | 55.5 | 89.0 | 132.3 |
| 16,384 | 50.8 | 88.1 | 36.5 | 55.5 | 87.4 | 140.7 |

No send would block; every receive of size 0 would block, and no other would.

Against S4 on the same DCS build, Wine version and method:

| Bytes | S4 frame p50 / p99 | Now frame p50 / p99 |
|---|---|---|
| 0 | 377 / 646 | 62.9 / 102.5 |
| 64 | 479 / 718 | 84.1 / 136.4 |
| 512 | 481 / 717 | 105.0 / 131.2 |
| 4,096 | 403 / 717 | 89.0 / 132.3 |
| 16,384 | 486 / 719 | 87.4 / 140.7 |

One `send` or `recv` costs 28–60 µs at p50, against 141–290 µs in S4. The Windows
client in S4 paid 19 µs at p50 for a 512-byte frame; this server pays about five times
that, on a different machine.

A frame of one `send` and one `recv` is still over E19's 10 µs whenever data is sent,
on both platforms, so E19's answer stands: the mapped file carries all data
(docs/adr/0002-mapped-file-transport.md). At about 111 frames a second a 512-byte socket
frame would take about 1.2% of real time, four times the agent's whole budget of 0.3%.

## The system-call frame

Microseconds, 600 frames:

| Call | p50 | p90 | p99 | max |
|---|---|---|---|---|
| `accept`, nothing waiting | 23.1 | 31.9 | 38.6 | 43.5 |
| Kill-switch check (`Path::exists`, absent) | 56.0 | 68.7 | 80.4 | 100.4 |
| Reload check (`Path::exists`, absent) | 37.7 | 40.1 | 55.7 | 61.0 |
| Log flush, one record held | 10.1 | 14.6 | 20.1 | 4,158.2 |
| Log flush, nothing held | 0.2 | 0.2 | 0.3 | 7.0 |
| Frame: `accept`, both checks, empty flush | 117.4 | 140.4 | 165.2 | 195.7 |
| Frame: `accept`, both checks, flush of one record | 127.7 | 153.2 | 188.5 | 4,280.6 |

The Frame rows add each frame's timed calls. They are not a timing of the whole frame,
which also does work without system calls.

No `accept` returned a connection. A file check costs as much as a socket call. A flush
with nothing held makes no system call. The slowest flush of 600 took 4.2 ms, seventeen
times the frame's 250 µs slice; the experiment records no other flush above p99, and
why it was slow is not established.

With a sidecar connected a `recv` (28.1 µs at p50, 46.3 µs at p99) replaces the
`accept`. That frame was not measured whole; its parts add to about 122 µs at p50.

Outside a handshake such a frame comes once a second. At about 120 µs a second it is
0.012% of real time, a twenty-fifth of the agent's budget. At p99 it takes two thirds
of the 250 µs slice with nothing to flush and three quarters with one record. During a
handshake there are up to ten such frames a second, about 0.12% of real time, for a
second or two.
