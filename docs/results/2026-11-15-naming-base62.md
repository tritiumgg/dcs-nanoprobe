# Platform names in base 62: the live check

Question: on a running DCS server, do the platform's base-62 names (spec/world.md,
"Names") reach DCS exactly, does the sidecar bind the objects under them, and does a
restarted sidecar bind them again from the names alone?

## Setup

- Tool: `cargo xtask commands <target> --part names --units 4`
  (`crates/xtask/src/commands/world.rs`), which runs `command-probe --part world
  --scenario names` (`crates/fake-agent/src/world_exit.rs`) in the game container as the
  sidecar. The same scenario runs against the stock-Lua mock in `lua/tests/world_exit.lua`.
- Campaign 1,763,000,000,000, tag `jqW`. One group of 4 `M-113`s and one `Hangar A`
  static, spawned through the sidecar's store and reconciler.
- DCS build: 2.9.31.29434, branch `dcs_server.release`.
- Platform: Linux dedicated server under Wine, `wine-10.0 (Debian 10.0~repack-6)`.
- Agent build: `37f90bb166287dc5`, a development build with the eval channel.
- Date: 2026-11-15. The tool restarted DCS and loaded a fresh shell mission first.

## Results

LIVE.

| Check | Result |
|---|---|
| Names DCS reported in `OBJECT` records | group `np!jqW1`; units `np.jqW2` to `np.jqW5`; static `np#jqW6` |
| Read in the `server` state by name | `Group.getByName('np!jqW1')`, its units' `getName()` and `StaticObject.getByName('np#jqW6')` returned each name exactly |
| Binding the agent reported | every unit with entity 2 to 5 and group entity 1; the static with entity 6 |
| After a sidecar restart (new link session, new reconciler from the kept store) | the first full enumeration reported the same names and entities; group and static stayed `live`; 0 spawns sent; 0 `foreign_name` |
| Removal | all 5 objects `OBJECT_GONE` with `DESTROYED` |

Verdict: pass (`names.json` in the run's bundle, not committed).

## Limits

- The agent binds a platform object from its name in both runs. The check shows that a
  sidecar with no memory of the binding rebinds from what the agent reports. It does not
  show a DCS restart with objects that a saved mission carries; the shell writer never
  saves platform objects into a mission.
- The run named entities 1 to 6, one base-62 digit each. Names with several entity
  digits, lower-case digits and the full 15 characters rest on E21b and E21c
  (docs/results/2026-11-15-s15-world-commands.md, docs/results/2026-11-15-e21c-farp-name.md).
